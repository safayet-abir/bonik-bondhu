# Deploying Bonik Bondhu (P7-T05)

Suggested free set-up (checked 15 Nov 2026 — free tiers change, confirm on the providers' pages):
**Render** free Docker web service (HTTPS, 750 h/month) + **Neon** free PostgreSQL (1 GB, does not
expire; Render's own free Postgres is deleted after 30 days). Any host that runs one container +
PostgreSQL with HTTPS works (TRD §8).

## Known limits of this set-up (say them if asked)

| Limit | Effect | What we do |
|---|---|---|
| Render free service sleeps after 15 min without traffic | first request after sleep takes ~1 min | open the URL 2–3 min before the demo |
| Ephemeral disk | receipt photos are lost on restart/redeploy (entries and drafts stay; the photo link answers 404) | demo photos are uploaded during the demo |
| Single instance | in-process rate limiter (TRD §8.5) | as designed |
| Neon idle suspend | first query after idle may take a few seconds | — |
| Proxy headers are trusted (`--forwarded-allow-ips *`) | a client can forge its IP for the per-IP auth limit; the per-phone lockout still applies | needed so one user cannot block every login behind the shared proxy IP |

## Steps

1. **Neon** — create a project in region *AWS Asia Pacific (Singapore)*. Copy the connection string and
   change only the scheme: `postgresql://…` → `postgresql+psycopg://…` (keep `?sslmode=require`).
2. **Render** — *New → Blueprint*, pick the GitHub repo and branch; it reads `render.yaml`. Enter the
   secret values when asked: `DATABASE_URL` (step 1), `GEMINI_API_KEY`, `GROQ_API_KEY`.
   `SECRET_SALT` is generated by Render. The first start runs `alembic upgrade head` (24 tables).
3. **Seed DEMO data and news from your laptop** (Render's free plan has no shell), in `backend/`:
   ```powershell
   $env:DATABASE_URL = "<the Neon URL from step 1>"   # this terminal only; never commit it
   $env:DEMO_PASSWORD = "<choose one; never shown on screen>"
   .\.venv\Scripts\python.exe -m app.cli seed-demo
   .\.venv\Scripts\python.exe -m app.cli import-news ..\data\news\curated_news.csv
   .\.venv\Scripts\python.exe -m app.cli fetch-news
   ```
4. **Smoke test** — `https://<app>.onrender.com/api/v1/health` → `{"status":"ok","db":"ok","llm":"configured"}`.
   Then the browser walkthroughs against the URL (`frontend/`, `DEMO_PASSWORD` set):
   `node e2e/p3-walkthrough.mjs https://<app>.onrender.com shots-p3` (likewise p4, p5, p6-ai-on; run
   `reset-demo` between them).
5. **Security checks on the URL** — response headers include `Strict-Transport-Security` and the CSP;
   the session cookie is `Secure; HttpOnly; SameSite=Lax`.
6. **Before the demo** — within the last hour: `reset-demo` (step 3 terminal), open the URL once to wake
   it, log in once on both demo browsers.

Never paste the Neon URL, API keys or `DEMO_PASSWORD` into chat, screenshots or the repo. Rotate a key
that ever appears in a commit, screenshot or recording (Security doc §5).
